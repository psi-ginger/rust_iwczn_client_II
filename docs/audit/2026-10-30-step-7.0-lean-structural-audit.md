### 3.2 Per-function assessment

- **`flow` (189 L, driver.rs:524)** — the depth scan confirms it is **not nested**: it is a
  linear orchestration script (front-connect → handshake → world-list → front-login → drop
  front → game-connect → handshake → game-login → char-list → select-char → world-entry →
  in-world). Markers recorded: ~8 `.await` phase boundaries, each a `DriverError::at(Stage::…)`
  call. This is cohesive by design — a driver *is* a sequence of stages. **Recommendation: keep
  as the top-level script**, but as 7.2 grows the in-world path, extract each stage into a
  private `async fn stage_*(…)` helper owned by a `Driver` struct so `flow` reads as a
  15-line table of stages. **Priority: ride-with-7.2** (only when the render loop adds real
  in-world work).
- **`parse_char_list_entry` (121 L) / `parse_chat` (78 L) / `parse_make_char_info_many` (70 L)**
  — flat guard-clause parsers over fixed-layout byte records (length gate → opcode gate →
  sequential field reads). **This is the natural, idiomatic shape for binary parsers**; forcing
  them into a trait/struct would *add* indirection without removing complexity. **Keep.**
- **`run_with_shutdown` (108 L, depth 7, event_loop.rs:346)** — the one genuine structural
  candidate. The depth-7 region is the **ticker catch-up loop** (`event_loop.rs:428-445`,
  recorded): `if state.deadline <= now { while state.deadline <= now { state.deadline +=
  interval } }`. Encapsulation proposal: move `TickerState` + its deadline-advance + fire logic
  into an inherent `impl TickerState { fn advance(&mut self, now) -> u64; fn due(&self, now) }`,
  shrinking `run_with_shutdown` to the select-loop skeleton. **Priority: ride-with-7.2** (the
  2D render loop will drive this same event loop with a frame ticker, so the cleaner the ticker
  state, the better).

### 3.3 Duplication (byte-parsing helpers)

**Command (reproducible):** collect every `fn NAME` across production files, group by name,
flag names appearing in >1 file; then print each duplicate's body for comparison.

**Recorded findings:**

- **Triplicated `i16_at`/`i32_at`/`i64_at`** — `game/char_info.rs:246,255,264`,
  `game/dispatcher.rs:424,429,439`, `game/world_entry.rs:379,388,397`. Recorded bodies are
  **near-identical**: all do `from_le_bytes` on a fixed-width slice; only the indexing style
  differs (`char_info`/`world_entry` use `payload[at..at+4].try_into().expect(...)`,
  `dispatcher` uses `payload[offset], payload[offset+1], …`). Same semantics, three copies.
- **Duplicated `le_u16`/`le_i16`/`le_i32`/`le_i64` + `cstr`** — `auth/login.rs:400,410,422` vs
  `auth/world_list.rs:351,363…`. Recorded bodies identical modulo the parameter name
  (`payload` vs `entry`).
- **Duplicated `copy_credential`** — `auth/login.rs:251` and `game/login.rs:181`.
- **Duplicated `gate_frame`** — `game/dispatcher.rs:462` and `game/world_entry.rs:407`.
  Recorded signatures identical (`cmd, expected_cmd, expected_len, payload`); bodies both check
  opcode then length. **Differentiator:** the error enums differ (`DispatchError` vs
  `WorldEntryError`). Recommendation: extract a shared `core` that returns
  `Result<(), (expected, got)>` (or a small `FrameGateError { kind, expected, got }`) and let
  each module `map_err` into its own enum — **not** blind dedup, to preserve each module's
  typed error surface (the repo's zero-evasion error convention).

**Recommendation (C1-C4):** introduce a shared little-endian byte-reader module (e.g.
`src/net/bytes.rs` or `src/protocol/le.rs`) exposing `le_u16/le_i16/le_i32/le_i64/le_i64` and
the `*_at` index helpers, plus the `cstr` reader and `copy_credential`. This is the single
highest-leverage lean action because **Step 7.1's asset decoders (SPR/MPR/Map/palette) will
read little-endian fields heavily** — landing the shared reader first means 7.1 reuses it
instead of adding a fourth copy. **Priority: ride-with-7.1.**

**Conclusion:** the only truly dead code is **`dispatch_frame`**. The 68 unit-test-only `pub`
