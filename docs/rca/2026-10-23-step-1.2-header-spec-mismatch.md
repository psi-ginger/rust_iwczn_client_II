# RCA: Step 1.2 Spec Describes a Wire Header/Checksum That Does Not Exist

- **Date**: 2026-10-23
- **Step**: Phase II, Step 1.2 ("GoonZu Wire Header & Checksum")
- **Detected by**: Implementing agent, during pre-implementation verification against `GoonZu_Source` (README Rule 1)
- **Severity**: Blocking (spec-vs-reality protocol mismatch; implementing as written would have fabricated wire behavior)

---

## Summary

Step 1.2 of `CONTRIBUTING.md` scoped an **8-byte** wire header
(`size: u16`, `checksum: u16`, `opcode: u16`, `param: u16`) and required
"the exact C++ checksum algorithm" verified by a bit-exact unit test.
Verification against the legacy C++ source and the server wire truth
(`rust_Iwcgz_server`) established that **no such header and no such
checksum exist**:

1. The legacy wire header is **5 bytes**, not 8: `usSize: u16`, `ucChk: u8`,
   `usCmd: u16` (`#pragma pack(1)`, `GoonZu_Source/NetworkLib/ITZNetLib/itzbase.h:63-68`).
2. The `ucChk` byte is **never computed and never validated** anywhere in the
   4,151-file legacy tree. It is not a checksum.
3. There is **no `param` field** in the header; a `usParam`/`param` search
   across all legacy `.h/.cpp` files returns zero protocol hits.
4. The only 8-byte framing that exists (`ntohs(size) + 8`) is the
   `headerType == 1` path, which **no call site in the entire legacy tree
   ever enables** (default is 0 everywhere), and the server port deliberately
   does not implement it.

Implementing Step 1.2 verbatim would have required inventing a checksum
algorithm and an 8-byte layout incompatible with the real server —
explicitly forbidden by CONTRIBUTING.md's zero-fabrication invariant.
Execution was halted per README Rule 3 and this RCA was filed.

## Root Cause

The Phase II WBS text in `CONTRIBUTING.md` was authored from an incorrect
model of the wire format, almost certainly by conflating:

- the **dead** `headerType == 1` receive/send branch
  (`ITZRecvBuffer.cpp:140-142,157-159`, `ITZSendBuffer.cpp:134-138`), which
  byte-swaps the size field and adds 8, into a belief that an 8-byte header
  with a `param` word is on the wire; and
- the never-validated `ucChk` **byte** in the real 5-byte header into a
  16-bit "checksum" field with an algorithm behind it.

Both beliefs are contradicted by the primary sources. There is no
intermediate layer, build flag, or regional variant (`_CHINA`/`_KOREA`/
`_JAPAN`) that turns either into reality: the header struct is identical in
both vendored `ITZNetLib` copies (`NetworkLib/ITZNetLib/itzbase.h:63-68`,
`GoonzuUserlog/GoonzuUserlog/ITZNetLib/itzbase.h:57-62`), and every producer
and consumer in the tree uses the same 5-byte `sPacketHeader`.

## Evidence

### Legacy C++ (primary source of truth for the client)

- **5-byte header**: `NetworkLib/ITZNetLib/itzbase.h:58-70`
  (`#pragma pack(1)` then `struct sPacketHeader { UI16 usSize; UI08 ucChk; UI16 usCmd; }`).
  `sizeof(sPacketHeader) == 5` is what every producer computes against
  (`CommonLogic/MsgType.h:2967` `usSize = sizeof(sPacketHeader) + datasize`;
  `Apex/ApexGoonZu.cpp:90`; `Server/FrontServer/FrontMsg.h` message structs).
- **Little-endian on the wire**: the default `headerType == 0` path reads
  `*(UI16 *)m_pCompletePtr` directly with no `ntohs` (`ITZRecvBuffer.cpp:155`)
  and copies bytes verbatim on send (`ITZSendBuffer.cpp:132`). The x86 host
  order is therefore the wire order.
- **Receive guards**: `ITZRecvBuffer.cpp:163` rejects declared size `< 2`;
  `ITZRecvBuffer.cpp:172` rejects `> PACKET_MAX_SIZE - 8` (= 64992,
  `itzbase.h:45` sets `PACKET_MAX_SIZE` 65000).
- **No checksum**: exhaustive searches over all 4,151 `.h/.cpp/.c/.inl`
  files found:
  - no assignment to `ucChk` (regex `ucChk\s*=` -> 0 hits);
  - the only reads are two debug log statements
    (`GoonZuWorld/Server/GameProtocol/GameProtocol.cpp:82,124`);
  - every `checksum`/`chksum` hit belongs to unrelated subsystems (zlib,
    ogg, IAF/Porte file-format checks, `NCryptHeader` file encryption in
    `NLib/NUtil.h`, patcher headers in `PATCH/Patch.h`).
- **`ucChk` is a cipher resync tag, not integrity**: on the encrypted game
  link the cipher overwrites header byte 2 with
  `pSrc[usSize - 1] + key1` (`NetworkLib/ITZNetLib/ITZEncrypt.cpp:44`).
- **`headerType == 1` is dead**: `CreateRecvBuffer`/`CreateSendBuffer`/
  `CreateFactory` call sites across the whole tree pass the default 0 (or
  omit the argument); no call site passes 1. The client itself uses
  `sf.CreateFactory(&sm, 2, 300000, 300000)` (`Client-Winsock.cpp:92`), and
  the FrontServer uses `m_SF.CreateFactory(..., 200*1000, 200*1000)`
  (`FrontClientProtocol.cpp:21`).

### Server wire truth (`psi-ginger/rust_Iwcgz_server`, HEAD `8e712af`)

- `crates/gz-net/src/lib.rs`: `HEADER_SIZE = 5`; `Frame::new` emits
  `[size LE u16][0u8][cmd LE u16]`; `Frame::integrity()` (offset 2) is
  documented: *"Deliberately **not** named `chk`, because it is not a
  checksum. No legacy producer ever writes it on a plain link and nothing
  ever validates it ... Treat it as reserved: do not build integrity on it."*
- `crates/gz-net/src/lib.rs:44-58`: *"`headerType == 1` is not implemented
  ... **No call site anywhere in the tree passes `headerType = 1`**"*;
  same in `crates/gz-net/reference/README.md:111` and
  `crates/gz-net/README.md:164`.
- `crates/gz-cipher/README.md`: `headerType == 1` framing is never combined
  with encryption; the cipher reads/writes little-endian; byte 2 on an
  encrypted link is the cipher's resync tag (vectors include
  `E7_decode_corrupt_checksum_slot`, a *cipher* anchor, not a checksum).

## Resolution

Per the QC Lead's decision (2026-10-23):

1. **Amended Step 1.2 in `CONTRIBUTING.md`** to the wire truth: 5-byte
   header (`size: u16` LE, `integrity: u8` reserved, `opcode: u16` LE),
   legacy receive guards (reject `< 2`, reject `> 64992`), the BUG-013
   divergence (reject 2..=4, parity with server `gz-net`), and the `0x8000`
   LZF compression-flag helpers. The fabricated "checksum algorithm"
   requirement was removed.
2. **Implemented `src/protocol/header.rs`** accordingly, with bit-exact
   little-endian layout tests and full guard-table tests.
3. `TASK_MATRIX.md` was **not** edited (QC Lead owns status entries).

## Prevention

- Steps **2.2 and 2.3** in `CONTRIBUTING.md` repeated the same defective
  premise ("extract 8-byte headers, verify size and checksum",
  "prepend 8-byte header; compute checksum"). Both were amended in the same
  change as Step 1.2 (approved by the QC Lead) to the 5-byte header with a
  reserved byte and no checksum.
- Any future step that touches framing must cite `itzbase.h` +
  `ITZRecvBuffer.cpp` (legacy) and `crates/gz-net` (server) as dual sources
  of truth (README Rule 1).
- The Step 1.2 guard-table tests pin `HEADER_SIZE == 5` and the
  `< 2` / `2..=4` / `> 64992` boundaries, so any regression toward an
  8-byte or checksum-bearing header model fails CI immediately.
